# Dotfiles: инструкции по работе

Общение с пользователем — на русском. Интерфейс (меню, уведомления, подписи) — на английском,
комментарии в коде — на русском.

## Начало и завершение работы
- В начале сессии прочитать разделы «Решения пользователя» и нужную задачу в `docs/agent-reference.md`.
  Это полный перенесённый трекер с картой конфигов, решениями, проверками и журналом.
  Выполнять задачу пользователя; когда задача не названа, ориентироваться на TODO трекера.
- Перед изменениями компонента прочитать его запись в «Карте конфигов», соответствующую задачу
  и последние записи «Журнала» в `docs/agent-reference.md`. Для темы — задача 11,
  quickdesk — задача 12, quickseek — задача 13. Старые версии, TODO и команды сверять
  с текущими файлами и более поздними записями. Пути в истории не переименовывать.
- В конце обновить статус соответствующей задачи и журнал в `docs/agent-reference.md`.
  Отделять применённые изменения от проверок, которые ещё должен выполнить пользователь.

## Правила работы
- Ничего не удалять и не перезаписывать в системе без явного согласия. Перед правками в /etc,
  загрузчике, юнитах systemd — показать diff/команды и спросить.
- Перед рискованным шагом (ядро, cmdline, udev, переезд на stow) напомнить про btrfs-снапшот
  (snapper настроен, grub-btrfsd включён → откат из GRUB).
- Не коммитить без просьбы. В репо есть незакоммиченный WIP пользователя — не смешивать
  со своими правками, коммитить отдельно.
- В коммитах и PR нет атрибуции ассистента, Co-Authored-By, ссылок на сессию и упоминаний AI.
- Сгенерированные файлы не править руками — править источник:
  - `hypr/hyprlock.conf` ← `binc/lock` при блокировке из `~/.cache/wallust/hyprlock.conf`
    ← wallust из `wallust/templates/hyprlock.conf.j2`
  - `~/.cache/waybar/config.jsonc` ← `waybar/scripts/launch.sh`
  - `~/.cache/wallust/*` ← wallust-шаблоны
  - `hypr/monitors.lua`, `hypr/monitors.conf` ← nwg-displays
- Hyprland с **Lua-конфигом**: API `hl.*`. Синтаксис `hyprctl dispatch` в Lua-режиме —
  Lua-выражение (`hyprctl dispatch 'hl.dsp.exit()'`). Старые вызовы вида
  `hyprctl dispatch dpms off` / `workspace N` проверить, прежде чем на них полагаться.
- Проверять результат вживую: `hyprctl reload`, `hyprctl monitors/clients -j`,
  `journalctl --user -b`, логи Hyprland (`$XDG_RUNTIME_DIR/hypr/*/hyprland.log`).


## Живая сессия и безопасные проверки
- Живой рабочий стол пользователя сохранять. Не создавать и не удалять headless-выходы
  в живом Hyprland без явного согласия: hotplug уже обрушивал приложения.
- Для UI нужен изолированный стенд; прежний путь `/tmp/claude-1000/stand/stand` —
  реальный исторический путь, не заменять в нём имя ассистента. Сначала проверить, что стенд
  ещё существует. Если его нет, подготовить изоляцию или обсудить способ проверки.
- Запускать только один необходимый тестовый композитор. Тестовые приложения — из отдельной
  копии, с собственными XDG-каталогами и IPC по PID; живые QML-демоны подхватывают правки.
- Завершить все запущенные для тестов процессы. После стенда: `stand stop`, проверить
  `pgrep -fa 'stand/.*test.lua'` и `pgrep -a kwin_wayland`, различая чужие процессы.
  Живой `Hyprland --watchdog-fd` сохранять; процессы завершать по установленным PID.
- Проверять основное окно и дочерние диалоги. Для требования «любая клавиша» проверять
  стрелки, Space, Enter и обычную букву. Успешная проверка в PTY не заменяет проверку в kitty.
- Скриншоты снимать только для тестируемого окна/слоя; личные окна пользователя не захватывать.
- Сначала предлагать простой лёгкий вариант. Фоновые процессы — пользовательские,
  без ненужного root и автоматики, с замером RSS, CPU и пробуждений.
- `./dot check` проверяет ссылки; воспроизводимость дополнительно требует проверки пакетов,
  `system/`, включённых юнитов и внешних репозиториев. Пересохранение юнитов и применение
  системных конфигов выполнять только в рамках поручения пользователя.

## Устройство репозитория
- GNU stow: пакет верхнего уровня повторяет путь от `$HOME`; `system/` копируется в `/etc`.
  Команды и объяснение — `docs/STOW.md`, `./dot --help`, `bootstrap.sh`.
- Исходные конфиги лежат внутри пакетов, например `hypr/.config/hypr/`.
  Сокращённые пути старого трекера разрешать относительно структуры stow.
- Код quickdesk и quickseek находится в отдельных `~/Apps/quickdesk` и `~/Apps/quickseek`;
  здесь находятся их настройки и интеграция. Читать AGENTS.md нужного репозитория перед его правкой.
- Машинные данные, карта конфигов, стекло, тема и уроки Quickshell — `docs/agent-reference.md`.
  Проверять нынешние версии и доступные мониторы; не хардкодить их набор.
- `~/.zshenv`, история clipse и секреты остаются локальными.

## Исходные решения пользователя (2026-10-04)
Поздние решения и результаты в `docs/agent-reference.md` имеют приоритет над исходным состоянием ниже.
- Dotfiles → **`~/dotfiles` + GNU stow** (пакеты по приложениям + `system/` для /etc,
  ставится скриптом; списки пакетов pacman/AUR; генерируемые файлы в .gitignore).
  После переезда **объяснить пользователю, как пользоваться stow** (и записать в `docs/STOW.md`).
- Теги обоев по содержимому: **локально через Ollama gemma4, только ручной запуск**. Новые обои
  в папке НЕ запускают автоматическую разметку. Нужна **группировка по содержимому и по цветам**.
- NVMe APST выключен ради быстрой загрузки (иначе ~40 с; вероятно, RAID/VMD в BIOS). Wi-Fi
  power_save/uapsd выключены из-за обрывов связи на 1–2 с. d3cold выключен, потому что после сна
  отваливался Wi-Fi. **Не откатывать вслепую.** Можно только предлагать точечные эксперименты
  с замерами и откатом (например, APST с ненулевым порогом латентности вместо 0).
- docker / libvirtd / kubelet → **запуск только по требованию** (socket-activation или
  запуск при вызове команды), не при загрузке.
- Hyprlock: проблема в **разном поведении в зависимости от того, откуда вызван**. Нужен один
  способ блокировки, одинаковый отовсюду. Других претензий к анимации нет.
- Навигация между мониторами: Super+стрелки / Super+Shift+стрелки двигают фокус/окно
  **внутри монитора, а у края надёжно переходят на соседний** в эту сторону (и для floating,
  и для пустых воркспейсов).
- Мониторинг батареи (уточнено 2026-11-07, см. задачу 6): своё GTK4-приложение + лёгкий пользовательский сборщик;
  оптимизация — только ручные настройки по одной с замером, `powertop --auto-tune` не используем.
