# Установка рабочего окружения

Установщик настраивает **уже установленный Arch Linux** от обычного пользователя с sudo.
Он не размечает диск, не устанавливает загрузчик и не переносит личные данные.

```sh
git clone --recurse-submodules https://github.com/Rymond044/dotfiles.git ~/dotfiles
cd ~/dotfiles
./bootstrap.sh
```

Если Python/gum отсутствуют, сначала предлагается установить только эти инструменты.
Далее показываются чекбоксы. В установленном gum 2 переключение — `x`, перемещение —
стрелками, подтверждение — Enter; актуальные клавиши написаны под списком. Ctrl+C отменяет
выбор. При отсутствии gum доступен текстовый список с `[x]` и переключением по номерам.

## Три части установки

| Часть | Что устанавливается |
|---|---|
| System | Обязательное окружение и штатные функции, основные приложения по умолчанию, собственные приложения/плагины, Oh My Zsh |
| User | Только отмеченные личные программы; изначально отмечены Telegram, Discord, KeePassXC и qBittorrent |
| Hardware | Только явно выбранные аппаратные опции; профиль MSI предлагается по модели, но не отмечается автоматически |

Исходник требований — `packages/scopes.json`. `pkglist.txt`, `aurlist.txt` и списки системных/
пользовательских служб содержат только общую базу. Снимки прежних смешанных списков лежат в
`packages/legacy/`, установщик их не использует. Обсуждение и первоначальный аудит всех
явно установленных пакетов сохранены в `package-scopes-proposal.md`; его историческая таблица
не заменяет актуальный JSON-каталог.

Среди обязательных приложений: Chromium, kitty, Nautilus, Neovim, EOG, mpv, Ark, Papers,
Evince, Bookworm, LibreOffice, GIMP и KFontView. Последний поставляется с plasma-workspace.
Библиотеки поиска, превью, калькулятора, OCR, темы и сборки собственных плагинов указаны как
требования окружения, даже если раньше были установлены случайно как зависимости.

Выбор user-программ не сохраняется отдельным личным профилем. При повторной установке
неотмеченные установленные программы не удаляются. Pacman выполняет полное обновление
Arch вместе с установкой выбранных пакетов; зависимости устанавливает пакетный менеджер.

Конфиги необязательных программ разворачиваются только при выборе соответствующей программы.
Локальный wallust.toml формируется из общего исходника с учётом выбора: без Codex CLI
и Ghostty не создаются и их файлы темы. GTK2 include получает текущий HOME вместо
сохранённого имени пользователя. Эти файлы и mimeapps.list — локальные результаты
установщика; исходники редактируются в репозитории, затем установка повторяется.
Новые MIME/URI-ассоциации создаются только для выбранных приложений. Уже существующие
ассоциации с доступными пользовательскими `.desktop` сохраняются, если база не задаёт
обработчик того же типа. Устаревшие ссылки Vesktop/Kando из исходного шаблона не добавляются.

## Просмотр плана без изменений

```sh
./dot plan
./dot plan --user telegram-desktop,discord,keepassxc,qbittorrent --hardware msi --features ai-tags
./dot plan --user none --hardware none --features none
```

`--plan` печатает JSON, не запускает команды, не скачивает файлы и не требует sudo.
Неуказанные выборы в этом режиме считаются пустыми: первая команда показывает чистую базу.
Идентификаторы user-программ — имена пакетов из каталога. Неизвестный ID останавливает
установщик до изменений.

Те же аргументы можно передать обычной установке; перед действиями остаётся подтверждение:

```sh
./bootstrap.sh --user telegram-desktop,discord --hardware msi --features none
```

## Ошибки AUR и повторный запуск

AUR-цели обрабатываются по одной и проверяются через pacman после каждой попытки.
Уже установленные пакеты не пересобираются. Если цель появилась в обычном репозитории,
установщик использует pacman. После первого прохода один раз повторяются только
оставшиеся неустановленные цели. Yay проверяется после обновления pacman/libalpm;
неработающий helper пересобирается отдельно.

Сбой одной AUR-цели не останавливает остальные пакеты, конфиги, приложения и настройку
служб. Неудачная подготовка темы откладывается; автологин новой системы не включается,
пока нет рабочих начальных конфигов рабочего стола и блокировки. Неполный результат
явно отмечается в конце и возвращает код 2 **после** остальных доступных шагов.
Отмена пользователем и критические ошибки pacman/системных конфигов по-прежнему останавливают установку.

Отчёт: `~/.local/state/dotfiles/install-report.json`.
Вывод сборки каждого пакета: `~/.local/state/dotfiles/install-logs/<timestamp>/<package>.log`.
Логи сохраняют вывод терминала, включая исходную причину ошибки.

Для `apple-fonts` предусмотрен исправленный рецепт `install/aur/apple-fonts/PKGBUILD`:
официальные архивы SF Pro и SF Compact обновились, их старые AUR-контрольные суммы больше
не совпадали. После отказа AUR автоматически собирается локальный `apple-fonts 7.0.6-2`
с проверенными SHA-256, всеми четырьмя семействами и отдельными лицензиями. Проверка
целостности не отключается. Полная реальная сборка проверена: 147 файлов шрифтов и четыре лицензии.

После обновления репозитория достаточно повторить bootstrap с нужными галочками:
установленные AUR-пакеты будут пропущены, отсутствующие — установлены.

## Аппаратные опции

- `msi`: MSI EC, управление зарядом/вентиляторами, Intel GPU/VA-API/firmware, обходы Wi-Fi,
  NVMe APST и PCI runtime PM; сохранённая раскладка мониторов и аппаратное окружение.
  Сюда же относятся экспериментальные GPU-флаги Chromium/Electron. В общей базе остаются
  Wayland и обычные пользовательские настройки; Electron-флаги создаются только для
  выбранных Electron-приложений.
- `scanner`: HP-сканер, его udev-правила и инструменты печати/сканирования.
- `xbox`: xpadneo, DKMS/headers и настройки Bluetooth/UHID. Старый xboxdrv не ставится вместе
  со вторым драйвером автоматически.
- `fingerprint`: fprintd и включение отпечатка в генерируемом hyprlock. После установки
  отпечаток нужно зарегистрировать (`fprintd-enroll`).
- `face`: Howdy. Регистрация лица и осознанное подключение к нужному PAM-стеку выполняются
  отдельно; установщик не переписывает аутентификацию вслепую.
- `btrfs`: Snapper/Btrfs + интеграция GRUB. Требует существующего Btrfs root и установленного
  GRUB; создание Snapper-конфига отдельно показывается и подтверждается.

Hardware не определяется расположением файла: `power-profiles-daemon`, ручные режимы и
Eco от батареи / Balanced от зарядки — общие. `ec-sync`, Cooler Boost, лимит заряда и
аппаратные обходы — только MSI. Без MSI EC соответствующие пункты Control Center скрыты.

Общие параметры существующего GRUB сохраняются отдельно от аппаратного cmdline. При выборе
MSI параметры добавляются по ключам, **cryptdevice/root и остальные параметры сохраняются**.
В mkinitcpio дополняется MODULES, существующие HOOKS не заменяются. Если cmdline GRUB
содержит shell-подстановки, установщик отказывается автоматически переписывать эту строку. Полные прежние снимки
сохранены в `hardware/msi/reference/`, а не применяются как универсальные конфиги.

System-настройки также включают согласованную блокировку/сон, Bluetooth и сеть. Wi-Fi
обслуживает iwd (quickseek/impala), остальные подключения — NetworkManager. Конфиги сначала
показываются через diff; службы включаются без `--now`. Автологин tty1 формируется с именем
текущего пользователя, вместо жёстко сохранённого rymond044. Оболочка zsh выбирается отдельным
подтверждением. `/etc/resolv.conf` установщик не заменяет: для iwd + systemd-resolved на
новой машине он должен указывать на корректный системный DNS-резолвер.

Перед применением boot/initramfs/udev изменений установщик напоминает о Btrfs-снимке.
Новые файлы `/etc`, enable-команды, пересборка initramfs и GRUB подтверждаются отдельно.

## Свои приложения, плагины и оболочка

`install/projects.json` фиксирует URL и коммиты:

- quickseek, quickdesk, linux-battery-monitor;
- hymission, HyprCapture, hyprglass;
- Oh My Zsh и autosuggestions, shift-select, syntax-highlighting, z.

Используется HTTPS — для клонирования не требуется заранее настроенный SSH-ключ GitHub.
Новые checkout создаются транзакционно. Существующие каталоги не перезаписываются и не
переключаются на другой коммит; локальные отличия явно отмечаются в выводе. Это сохраняет
работу пользователя, но такая установка уже содержит локальные отклонения от lock-файла.
Для quickdesk зафиксирован опубликованный fff7fbd: местный f90d494 добавляет только AGENTS.md.

Battery Monitor устанавливается с unit/desktop/icon, без запуска сборщика немедленно.
Сборка и регистрация плагинов выполняется автоматически **при следующем графическом входе**
через `dotfiles-first-login.service`, который открывает kitty с ходом сборки. Если
`hyprpm` запросит sudo-пароль для установки заголовков, введите его в этом терминале.
При успехе окно закрывается, при ошибке остаётся открытым до Enter.
Текущая сессия установщиком не перезагружается.
Пока плагины собираются, конфиг Hyprland допускает их отсутствие.

Сервис проверяет ошибки сборки и наличие helpers, загружает плагины и восстанавливает
Neovim-плагины по lazy-lock. Только после успеха создаётся маркер завершения. CPU сборки
ограничен квотой двух ядер, приоритет понижен. После завершения процесс не остаётся в фоне.
У существующих hyprpm-регистраций проверяется коммит сборки: имя ветки `local` само по
себе не мешает повторной установке. Чужие регистрации сохраняются; при непустом кэше
глобальный `hyprpm update` не запускается. Если старые заголовки несовместимы с новым
Hyprland или нужный коммит отличается, сервис сообщает об этом и оставляет обновление
на ручное согласование. Кэш не удаляется для повторного добавления автоматически.

```sh
systemctl --user status dotfiles-first-login.service
journalctl --user -u dotfiles-first-login.service
```

Если старая версия сервиса упала с ошибкой sudo `conversation failed`, завершите
настройку из терминала внутри Hyprland (запускайте от своего пользователя):

```sh
cd ~/dotfiles
env DOTFILES_FIRST_LOGIN=1 python3 install/installer.py --first-login
```

При успешном завершении создаётся тот же маркер; повторная установка не требуется.

Совместимость закреплённых плагинов с будущим Hyprland не гарантируется. При ошибке сервис
показывает уведомление, не отмечает установку завершённой и оставляет вывод в терминале.
Нужен пересмотр
закреплённых ревизий, а не автоматический переход на произвольную ветку.

## Секреты и начальные изображения

Из `install/templates/.env.example` создаётся `~/.config/dotfiles/.env` с правами 600.
Из `.zshenv.example` создаётся `~/.zshenv`, который экспортирует значения из локального env.
Оба существующих файла сохраняются. Если ~/.zshenv уже был своим, он не переписывается:
при желании подключение нового env нужно перенести из шаблона вручную. Реальные секреты
установщик не читает и не копирует в репозиторий. Подключение Cargo и kubectl completion
условное: их отсутствие не ломает оболочку.

Пять изображений из `wallust/.local/share/dotfiles/defaults/wallpapers/` копируются в
`~/Wallpapers` без замены существующих одноимённых файлов. При отсутствии `current`
случайно выбирается одно из этих пяти; при повторном запуске текущий фон сохраняется.
Выборщик индексирует изображения и подготавливает тему без перезагрузки приложений.
Аватарка-свинка копируется в `~/Pictures/pfp/current_pfp.jpg`, только если своего файла нет.

Галочка `ai-tags` ставит Ollama + Vulkan backend и предлагает скачать Gemma. Скачивание
использует временный сервер на отдельном порту; он завершается в finally. Сервис Ollama и
автоматическая разметка не включаются. Без опции выбор обоев/цвета/избранное/ручные теги
работают; Tag with Gemma выдаёт понятное уведомление и не оставляет ложный прогресс.

## Источники необязательных пакетов

Multilib добавляется только при выборе Steam/lib32-пакетов. При выборе ChatGPT отдельно
показываются конфиг официального репозитория и импорт встроенного публичного ключа с
проверкой fingerprint. Проверка подписей не отключается. OpenAI Codex CLI устанавливается
из обычного репозитория Arch. Целиком старый `/etc/pacman.conf` не копируется.

## Бэкапы и обслуживание

Конфликтующие домашние конфиги после подтверждения сохраняются в
`~/.dotfiles-backup/<timestamp>/`. Ссылки сохраняются с суффиксом `.symlink`, чтобы ссылка
на папку не перенаправляла последующие бэкапы в исходный репозиторий. Folded-папки stow
безопасно разворачиваются перед созданием локальных генерируемых файлов.
Бэкапы `/etc` находятся в `/var/backups/dotfiles/<timestamp>/` с закрытыми правами каталогов
и сохранением метаданных исходных файлов.

```sh
./dot pkgs diff       # неизвестные явно установленные пакеты
./dot pkgs save       # такой же аудит; scopes не смешиваются
./dot pkgs export     # обновить четыре системных списка из scopes.json
./dot check           # обязательные ссылки, без генерируемых/локальных файлов
./dot units diff      # базовые enable-списки; ошибка D-Bus не выдаётся за отсутствие служб
./dot sys diff        # только общие system/, hardware проверяется выбранным планом
```

## Проверка реализации

```sh
python -m unittest discover -s install/tests -v
```

На 2026-11-20 проходят 30 тестов. Они используют временный HOME, настоящий stow и отдельные PTY для галочек; root-операции
не применяются. Покрыты scopes, ассоциации, повторный запуск, сохранность исходников при
folded-ссылках, секреты, изображения и запуск Tag with Gemma без Ollama.
Дополнительный файловый прогон (нужны bwrap, stow и установленные зависимости темы):

```sh
python -u install/tests/smoke_install.py
```

Он запускает базу, MSI с четырьмя отмеченными приложениями, ChatGPT + Steam и сценарий
с отказавшим AUR-пакетом; каждый
сценарий проходит первый и повторный запуск. Настоящая система и исходники доступны
только для чтения, сеть отключена. stow, индексирование обоев, генерация темы и файлов
работают по-настоящему; pacman/yay/git и управление службами заменены тестовыми командами.
Проверены также изменение источников пакетов и сохранение шифрованного root в cmdline.
Пакет apple-fonts дополнительно действительно собран из официальных DMG вне этого прогона,
проверены архив пакета, все четыре лицензии и SF Pro Display Bold через fontconfig.
Файловый прогон **не** проверяет скачивание/сборку остальных пакетов и графический первый вход.
Проверка полной установки/сборки всех пакетов на чистом Arch и графического первого входа
в VM остаётся отдельной проверкой. Текущая живая система при разработке не разворачивалась.
